# 2026-09-18：追爆桌面 Broker 保留智能体元数据

## 问题与证据

追爆插件按当前智能体和对话检查任务归属，但桌面 Broker 原先无条件删除 `x-agent-id`。平台 `main`（`07e28e9`）的 `DshAgentPrincipalGuard.bindDesktopBrokerPrincipal` 已支持合法智能体元数据；缺失时退回 `desktop-workbench`，可能造成任务创建后被插件归属检查隐藏。

## 修改范围

- 仅对已经通过原有路由白名单、且 runtime 持有桌面登录会话的 `/api/v1/viral/` 请求，保留格式合法的 `x-agent-id`。
- 格式与服务端一致：1–128 位 ASCII 字母、数字、点、下划线、冒号或连字符，首位必须为字母或数字。非法值直接过滤，不转发。
- 其他路由及未登录 runtime 继续过滤该字段。租户、用户、Cookie、授权和 `x-opc-*` 签名字段的原有过滤不变，登录 Cookie 仍仅由主进程注入。
- 不修改授权、审核、费用门禁、上传和媒体转发，不调用付费 API。

## 验证

- 先加回归测试：4 个合法追爆路由均因实际转发值为 `null` 失败，确认能捕获原缺陷。
- 修复后 Broker 测试 27/27 通过；包含大小写 header、恶意字符、超长和非字符串值、其他路由、未登录 runtime、伪造租户和签名过滤。
- TypeScript 检查通过。
- 桌面全量测试 118 个文件、882 项通过；独立只读安全复审无阻断发现，并复跑 Broker 27 项测试通过。
- 依赖审计发现既有 `image-size → pptxgenjs → dsh-ppt` 链路的 4 项 high 提示（解析器拒绝服务风险，无可用修复）；本次未更改依赖，不宣称仓库依赖已无漏洞。
- 这是 Broker 边界修复，真实桌面新建任务及刷新恢复仍需主任务在合并打包后验收；不能据此宣称完整生产链路已通过。

## 来源与边界

来源：本次一键追爆 Profile/桌面真实链路修复中的独立小阶段。服务端版本支持已由当前平台 main 源码确认，线上部署状态须另行核实。智能体 ID 是已认证 runtime 提供的范围元数据，不能替代服务端用户、租户身份验证。
